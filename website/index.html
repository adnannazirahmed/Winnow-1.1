01 / Why graph-first

Policies don't fail in isolation. Paths do.

Winnow starts with the permission graph, not a checklist. It evaluates effective access across identities, policies, groups, roles, and trust edges, then keeps the evidence that made the path possible.

01

Effective permissions

Allow, Deny, wildcards, NotAction, NotResource, and conditions are evaluated together, so a policy is judged by what it actually grants.

02

Trust relationships

Assume-role edges are followed only when the source can assume the role and no explicit deny covers it.

03

Retained evidence

Every finding keeps the matched statement, decision status, and the runtime context the input cannot prove.

05 / How it works

Findings stay tied to evidence.

The deterministic engine evaluates the evidence. AI is optional, bounded, and explicit about failure. Local AWS scans are read-only by design.

Read the security notes

Deterministic core

Findings and graphs work without an AI provider. No key, no gate.

Bounded AI

AI remediation is capped at 5 uncached calls per analysis and cached by finding content.

Read-only AWS · local

Run Winnow locally to scan AWS using GetAccountAuthorizationDetails and GetCallerIdentity.

No mutation

Remediations are proposals. Winnow does not change IAM.
